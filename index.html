What it is

Aerini is an app for building automation visually: drop nodes onto a canvas, connect them with wires, and the resulting graph is your workflow. Nothing runs until you start it, and when it does, it runs on hardware you control.

NodeOne block, one job: fetch a URL, filter a list, call a model.
WireThe path data takes from one node's output to the next node's input.
WorkflowA saved graph of nodes and wires, ready to run on demand or on a schedule.

Trigger

A run starts here: by hand with Manual Trigger, or in the background from a Schedule or Webhook.

Action

Fetches, transforms, or calls out to something external. HTTP Request has separate Success and Error outputs, so a failure can be wired somewhere on purpose.

Utility

Marks the result. Output shows what the workflow produced; other nodes write it to a file or send it to another service.

What you can build

Whatever you'd otherwise write a script for.

A sample of what people build with it, not an exhaustive list.

Trigger

Webhook receivers

Turn an incoming HTTP request into the start of a workflow. The listener runs inside Aerini, bound to localhost.

Action

Scheduled reports

Pull data on a timer, shape it, and send it out as a file, message, or email.

AI

AI pipelines

Chain model calls with your own logic in between: retries, filters, and branching included.

Logic

Alerts & monitors

Poll something on a loop and branch on the result. Only notify when a condition actually changes.

Utility

File processing

Watch a folder, reshape what lands in it, and write the result somewhere else. Folder watching is the File Watcher plugin on Patreon: included for supporters, or available to buy on its own.

Action

Cross-posting & uploads

Push the same output to several destinations from one workflow instead of several scripts.

Utility

Embeddable chat widget

Put a floating chat window on any web page, backed by a Webhook workflow. One script tag on the page; the workflow is served by aerini-server in api mode.

Flow control

Branch-and-merge pipelines

Loop over a list, fan out to parallel branches, then merge the results back into one path before continuing.

Integration

Two-way app sync

Read from one system, reshape the data, and write it to another, on a schedule or when a webhook arrives.

Why Aerini

Decisions that shape everything else.

Utility

Runs itself, not a subscription

No account to create, no cloud dependency, no telemetry. Aerini's own interface loads one font from Google Fonts. The only other call it makes is checking for updates, and only when you click Check for Updates.

Action

An engine, not just an app

The workflow engine is a standalone Rust crate. Embed it in your own program, register custom nodes in code, and run it with no UI attached at all.

crate: aerini-engine

Logic

Plugins that can't reach your filesystem

Third-party nodes compile to WebAssembly and run in their own Wasmtime sandbox: no filesystem access, a memory cap, and a time limit per call. Outbound HTTP is filtered the same way built-in nodes are, so a plugin can't reach your internal network.

target: wasm32-wasip2 · 64 MiB memory · 30 s per call

Trigger

One engine, two ways to run it

Build and test in the desktop app, then use Export → Export for Server to package the workflow for aerini-server, a headless binary. The Linux target is a zip with a systemd service.

Action

Built to be watched while it runs

A Monitor panel shows memory, active runs, and per-workflow status live, not bolted on after the fact.

Logic

Install plugins without leaving the app

Open the Plugins panel, choose a plugin folder once, then install nodes with the file picker or by dropping a file on the window. Multi-node packs install and remove as one group. Each plugin shows its signature status (unsigned is normal for community plugins), and one that fails to load shows why.

formats: .wasm · .aerinipkg (multi-node packs)

AI

AI nodes that don't need a hosted API

Point AI Prompt or AI Agent's Base URL at Ollama or any OpenAI-compatible server on your own machine or network, and the request stays there.

Most people never touch that condition. If it matters for what you're building, a commercial license removes it for one named product.

  • macOS: the app is not signed with an Apple Developer certificate. The first time, right-click it and choose Open. There is no Intel build yet.
  • Windows: the installer is not code-signed, so SmartScreen will warn you. Choose More info, then Run anyway.
  • Linux: needs webkit2gtk 4.1, which most desktops already have.

Building from source: git clone https://github.com/Panchak2d/Aerini.git. See the repo's docs/ folder for engine-embedding and plugin-authoring guides. Running the headless engine unattended (aerini-server): docker pull ghcr.io/panchak2d/aerini-server, or build the image yourself if you want to customize it; see the deployment guide above.
